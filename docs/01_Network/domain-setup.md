# Domain Setup

> [!NOTE]
> #DNS #DDNS #Networking

This guide covers how to point your custom domain subdomains to your homelab using CNAME records and the MikroTik DDNS service.

## 1. Prerequisites
- A domain registered with Namecheap.
- MikroTik DDNS enabled (refer to `mikrotik/setup.md`).


## 2. Configuring Namecheap DNS

1. Log in to [Namecheap](https://www.namecheap.com).
2. Navigate to **Domain List** → **Manage** → **Advanced DNS**.
3. For every subdomain you wish to use (e.g., `nextcloud`, `jellyfin`), create a **CNAME Record**:
   - **Type:** `CNAME Record`
   - **Host:** `[SUBDOMAIN]` (e.g., `nextcloud`)
   - **Value:** `[DDNS_NAME].sn.mynetname.net`
   - **TTL:** `Automatic` (or `60 min`)

> [!TIP]
> Using a CNAME record pointing to your MikroTik DDNS URL ensures that your subdomains always resolve to your current public IP address without needing a local update script.


## 3. Email Setup & Security Records (SPF & DMARC)

> [!TIP]
> **Preferred Architecture: Free Namecheap Email Forwarding + Catch-All**
> 
> Using Namecheap's free **Email Forwarding** and **Catch-All** feature to route incoming domain emails (`anything@[DOMAIN]`) to a personal email inbox is the preferred setup. It provides custom domain branding, hides your real personal address, allows unlimited aliases on the fly, and requires zero mail server maintenance.

### Preferred Setup: Namecheap Email Forwarding + Catch-All

To configure free domain email forwarding with full SPF/DMARC anti-spoofing protection:

1. **Configure Mail Settings (Advanced DNS Tab)**:
   * Scroll down to **Mail Settings** at the bottom of the page.
   * Select **Email Forwarding** from the drop-down menu and save.
   * *Namecheap will automatically publish its forwarding MX records (`efwd1.registrar-servers.com` ... `efwd5.registrar-servers.com`).*

2. **SPF Record (Auto-managed by Namecheap)**:
   - **Type:** `TXT Record`
   - **Host:** `@`
   - **Value:** `v=spf1 include:spf.efwd.registrar-servers.com ~all`
   - **TTL:** `Automatic`

3. **DMARC Record**:
   - **Type:** `TXT Record`
   - **Host:** `_dmarc`
   - **Value:** `v=DMARC1; p=quarantine;` (or `p=none;`)
   - **TTL:** `Automatic`

4. **Enable Forwarding & Catch-All (Domain Tab)**:
   * Navigate back to the main **Domain** tab → Scroll down to **Redirect Email**.
   * Select **Set Up Catch-All** (or add specific aliases like `contact` or `admin`).
   * Enter your personal destination email (e.g., `yourname@provider.com`).
   * Click the green checkmark to save.
   * **Verification**: Click the one-time verification link sent by Namecheap to your personal email inbox.

---

### Alternative 1: Defensive "No-Send" Configuration (If no email is used)

If a domain is parked or purely used for web services with zero email activity:

1. **SPF Record**: `v=spf1 -all`
2. **DMARC Record**: `v=DMARC1; p=reject;`
3. **Mail Settings**: Select **No Email Service** (Null MX).
4. **Wildcard DKIM Revocation**: `TXT` record at `*._domainkey` with `v=DKIM1; p=`.

### Alternative 2: Paid Managed Provider (e.g., Proton Mail, M365, Google Workspace)

If upgrading to a paid custom domain mailbox:

* **SPF**: Update to authorise your provider (e.g., `v=spf1 include:_spf.protonmail.ch ~all`).
* **DKIM**: Add selector `CNAME` / `TXT` records generated by your provider.
* **MX Records**: Set custom MX records pointing to your provider's mail hosts.
* **DMARC**: Keep `_dmarc` active (`p=quarantine` or `p=reject`).

### Alternative 3: Self-Hosted Email Stack (e.g., Mailcow, Stalwart, Mailu)

If self-hosting a mail server stack on a dedicated Cloud VPS with custom Reverse DNS (PTR) delegation:

* **A/AAAA Record**: Create an A record for your mail server (e.g., `mail.[DOMAIN]` → `[PUBLIC-IP]`).
* **MX Record**: Point `@` to `mail.[DOMAIN]` (Priority `10`).
* **SPF**: Authorise your VPS IP (`v=spf1 mx ip4:[PUBLIC-IP] ~all`).
* **DKIM**: Publish public key `TXT` record at `<selector>._domainkey`.
* **Reverse DNS (PTR)**: Configure PTR record with VPS provider (`[PUBLIC-IP]` → `mail.[DOMAIN]`).


## 4. Verification

### Online Verification (MXToolbox SuperTool)
Verify your DNS security records online using [MXToolbox SuperTool](https://mxtoolbox.com/SuperTool.aspx):

* **SPF Check**: Enter `spf:[DOMAIN]` to confirm `v=spf1 -all` is active.
* **DMARC Check**: Enter `dmarc:[DOMAIN]` to verify `p=reject` policy enforcement.
* **MX Check**: Enter `mx:[DOMAIN]` to confirm the Null MX record or "No Email Service" setting.
* **DKIM Check**: Enter `txt:*._domainkey.[DOMAIN]` to check DKIM key revocation.

### Local CLI Verification
Verify DNS resolution locally from your workstation:

```bash
# Check if the subdomain resolves to your MikroTik DDNS address
nslookup nextcloud.[DOMAIN]

# Verify SPF and DMARC TXT records
dig +short TXT [DOMAIN]
dig +short TXT _dmarc.[DOMAIN]
```

## Appendix: Legacy DDNS Method

> [!WARNING]
> This method is legacy and has been replaced by the CNAME method described above. It is kept here for historical reference or for cases where CNAME records cannot be used.

Previously, a custom bash script was used to update A records for subdomains.

### 1. Installation
Install the required libraries:
```bash
sudo apt update 
sudo apt install dnsutils
```

### 2. Configuration
1. Update the custom DDNS updater script (e.g., `update-ddns.sh`) with your subdomain keys.
2. Set the script to run via `crontab`:
```bash
*/10 * * * * /[PATH-TO-SCRIPT]/update-ddns.sh
```
